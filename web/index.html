      How your file is protected

      Each step is tagged by the kind of technique it uses.

      5Classical
      1Post-quantum
      1AI model
      1. Argon2id Classical
        Turns your passphrase into the key-encryption key. Memory-hard, so guessing is slow.
      2. ML-KEM-768 (Kyber) Post-quantum
        NIST FIPS 203. Every file key is wrapped to the vault's ML-KEM public key, protecting stored files against "harvest now, decrypt later" quantum attacks. HKDF-SHA256 turns the shared secret into the wrapping key.
      3. AES-256-GCM Classical
        Encrypts each file and its name under its own random key, and detects any modification.
      4. SHA-256 Classical
        Fingerprints each stored ciphertext so corruption or swapping is caught before decryption.
      5. Hash-chained audit log Classical
        Every action links to the hash of the previous one, so editing history breaks the chain.
      6. Isolation Forest AI model
        Learns what normal access looks like (hour, request rate, data volume, failed unlocks, files touched) and flags outliers. Alerts are written into the audit chain.

      Post-quantum means resistant to quantum computers. It runs on ordinary hardware. This demo uses a pure-Python ML-KEM and an AI model trained on simulated logs.

      Hosted mode is not zero-knowledge

      In this web app the server does the decryption, so it briefly handles your passphrase and file while serving a request. Use HTTPS only. For fully local encryption use the command-line tool.
